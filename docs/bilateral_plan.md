# 4ch バイラテラル制御の実装計画

SO-101 のリーダーとフォロワーで、4ch バイラテラル制御（位置と力の双方向伝達）を実装するための計画です。
作業を引き継ぐエージェントは、この文書の「進捗」を更新しながら進めてください。

## 背景

参考にしたのは、境野 翔 氏（筑波大）の 2026-11-09 の投稿です。
https://x.com/shosakaino/status/2119795666457350203

投稿の要点は次の2つです。

- SO-101 で 4ch バイラテラル制御を実現した
- STS3215 にはトルク制御モードがないため、PWM で擬似的にトルク制御している

ゲイン、制御周期、コードは公開されていません。
そのため、境野研で標準的な「加速度ベースの 4ch バイラテラル（DOB と RFOB を使う）」を前提にしています。

## 前提となる環境

- 実機は Ram（この PC、GPU なし）から動かす。ポートは `/dev/so101-leader`（5V）と `/dev/so101-follower`（12V）
- LeRobot 0.6.1（`.venv`、`uv run` で実行）
- シミュレーションと同定は tachyon（`~/so101/mujoco`、`scripts/fit_servo.py` の流れ）
- 使うレジスタ（`lerobot/motors/feetech/tables.py` の STS/SMS 表）

| 名前 | アドレス | 用途 |
|---|---|---|
| `Operating_Mode` | 33（EEPROM） | 2 = PWM 開ループ、0 = 位置サーボ |
| `Torque_Enable` | 40 | トルクの ON と OFF |
| `Goal_Time` | 44 | PWM モードでの PWM 指令値（方向ビットつき） |
| `Torque_Limit` | 48 | 出力の上限（PWM モードで効くかは未確認） |
| `Lock` | 55 | EEPROM 書き込みの前に 0 にする |
| `Present_Position` / `Present_Velocity` | 56 / 58 | 角度と速度 |
| `Present_Current` | 69 | 電流。1 単位は約 6.5 mA（`teleop_power_log.py`） |

## 制御則

関節ごとに、リーダー (l) とフォロワー (f) に次の目標を課します。

- 位置の一致：θ_l − θ_f → 0
- 作用・反作用：τ_l + τ_f → 0

```
τ_l^ref = J·[-Kp(θ_l−θ_f) − Kd(ω_l−ω_f)]/2 − Kf(τ̂_l+τ̂_f)/2 + τ̂_dis,l
τ_f^ref = J·[+Kp(θ_l−θ_f) + Kd(ω_l−ω_f)]/2 − Kf(τ̂_l+τ̂_f)/2 + τ̂_dis,f
```

- τ̂_dis は外乱オブザーバ（DOB）の推定値
- τ̂ は反力推定オブザーバ（RFOB）で求めた外力（外乱から重力と摩擦を引いたもの）

トルク指令から PWM への換算は、モータの簡易モデルで行います。

```
duty = (R/Kt · τ_ref + Ke · ω) / V_supply
```

逆起電力 Ke·ω を補償することが「擬似トルク制御」の要点です。
duty を `Goal_Time` の値域と方向ビットに変換して書きます。

## フェーズ

### 0. PWM モードの単関節確認

最初は wrist_roll や gripper など、暴れても安全な関節で行います。

- `Lock` を 0 にして `Operating_Mode` を 2 に書く。終了時は必ず 0 に戻す。戻さないと `teleop.sh` や方策の実行が壊れる
- 次の3点を実測する
  - PWM の方向ビット。lerobot のコメントは bit11 だが、資料によっては bit10
  - `Torque_Limit` が PWM 出力に上限をかけるか
  - `Present_Current` に符号があるか
- PWM モードでは位置リミットが効かない。最初から次を入れる
  - ソフトウェアによる角度制限
  - 例外時と Ctrl+C では PWM を 0 にしてトルクを OFF にする
  - 温度と電流の監視

完了条件：PWM 値と回転方向・速度の対応表、方向ビット、電流の符号が分かっていること。

### 1. 高速 I/O 層（`scripts/bilateral/bus.py` を新規作成）

- lerobot の `Robot` クラスを通さず、`FeetechMotorsBus` の `sync_read` と `sync_write` を直接使う
- 各周期で Position、Velocity、Current を読み、`Goal_Time` を書く
- 2本のバスをスレッドで並列に動かす
- 周期を実測して目標周期を決める。200〜500 Hz を狙う（1 kHz は難しい見込み）

完了条件：両腕 6 関節の読み書きを含む1周期の時間の分布（平均と最悪値）が分かっていること。

### 2. モータモデルの同定（関節ごと、アームごと）

- 一定 PWM の掃引から Kt/R、Ke、クーロン摩擦、粘性摩擦を求める
- いくつかの姿勢で静止を保つ PWM から重力項を求め、tachyon の MuJoCo モデルと照合する
- チャープ入力から慣性 J を求める。`step_response.py` と `fit_servo.py` の流れを流用する
- 結果は `calibration/bilateral/{leader,follower}.json` に保存する

### 3. 片腕でのトルク制御の検証

1. 重力と摩擦の補償だけをかけ、手で軽く動かせることを確認する（最初の目標）
2. PWM による PD 位置制御、DOB、RFOB を順に足す
3. 既知の重りで外力推定の精度を確認する

### 4. 1関節での 4ch バイラテラル

- wrist_flex か shoulder_pan の1関節で両腕を結合する
- Kp、Kd、Kf と、オブザーバのカットオフ（g_dis、g_reac）を調整する
- 自由運動での追従と、物を押したときの力の伝わり方を記録して評価する

### 5. 全6関節への拡張

- gripper を含めて拡張し、ゲインは関節ごとに持つ
- ログを可視化するスクリプトを用意する

### 6. （任意）模倣学習用データの記録

- θ、ω、τ̂ をリーダーとフォロワーの両方で記録し、既存の `scripts/record.py` に統合する
- 境野研の「バイラテラル制御に基づく模倣学習」を行うためのもの

## リスクと対策

- リーダーとフォロワーで駆動系が違う。リーダーは 5V で関節ごとに減速比が違い、フォロワーは 12V で 1/345。リーダーは出せるトルクが小さく摩擦が大きいため、伝えられる力の上限と透明性はリーダーで決まる。対策は力のスケーリングと摩擦補償。足りなければ、リーダーもフォロワーと同じ仕様にすることを検討する（ユーザーの判断が必要）
- `Present_Velocity` の分解能が低い。位置を擬似微分し、20〜50 Hz 程度のローパスをかけて使う
- EEPROM の書き換え回数に上限がある。モード切替は起動時と終了時の1回ずつにとどめる
